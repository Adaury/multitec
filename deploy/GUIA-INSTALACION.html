Lo que necesitas tener

  • Un servidor o PC con Windows Server 2019 o más nuevo (o Windows 10/11 Pro), 8 GB de RAM (16 GB si vas a usar la IA) y 50 GB libres.
  • Usuario administrador del servidor.
  • Internet en el servidor durante la instalación.
  • Una memoria USB para llevar los ZIP.
  • El dominio (por ejemplo multitec.com.do), si lo vas a abrir a internet. Puede esperar: primero se puede instalar para la red local.

AEn tu PC actual

  1. Abre la carpeta C:\laragon\www\multitec.
  2. Doble clic en EMPAQUETAR.bat. Espera a que diga «Listo». Crea MultitecServidor_FECHA_versión.zip (el programa, sin datos ni claves).
  3. Doble clic en EXPORTAR-DATOS.bat. Crea MultitecDatos_FECHA.zip con tu base de datos, fotos y configuración (datos de la empresa, correo, precios).
  4. Copia los dos ZIP a la memoria USB. Están en C:\Users\Usuario\MultitecServidor.
Más fácil: un solo archivo. En vez de los pasos 2 y 3, doble clic en EMPAQUETAR-COMPLETO.bat. Crea MultitecCompleto_FECHA_versión.zip con todo: el programa, tus logos y los de los aliados, los videos, y tus datos (clientes, cotizaciones, fotos, planes, configuración). En el servidor lo extraes en C:\Multitec y ejecutas INSTALAR.bat: encuentra los datos solo.
Cuidado con el ZIP de datos: tiene la información de tus clientes y la clave del correo. No lo mandes por WhatsApp ni correo, no lo subas a GitHub ni al OneDrive del trabajo. Bórralo de la USB cuando el servidor funcione.
Haz la exportación justo antes de mudarte: lo que se cree en la PC vieja después de exportar no pasa al servidor. Desde ese momento usa solo el servidor.

BPreparar el servidor Solo la primera vez

B1. Actualiza Windows

Configuración → Windows Update → instala todo y reinicia.

B2. Instala Python

  1. Descarga Python 3.14 de python.org/downloads.
  2. Al abrir el instalador marca «Add python.exe to PATH» (abajo) y luego Install Now.

B3. Instala PostgreSQL 17

  1. Descárgalo de postgresql.org/download/windows (instalador de EDB, versión 17).
  2. Deja todo como viene. Cuando pida una contraseña para el usuario postgres, pon una segura y anótala: el instalador de Multitec la pide una vez.
  3. Puerto: 5432 (el que trae). Al final, no hace falta abrir «Stack Builder».
NSSM y Caddy (los programas que dejan Multitec funcionando como servicio y publican la web) los instala INSTALAR.bat solo.

CInstalar Multitec

  1. Crea la carpeta C:\Multitec en el servidor.
  2. Copia ahí los dos ZIP. Clic derecho en MultitecServidor_….zip → Extraer todo… → destino C:\Multitec.
  3. Deja el MultitecDatos_….zip sin extraer dentro de C:\Multitec: el instalador lo encuentra solo.
  4. Doble clic en INSTALAR.bat y acepta el permiso de administrador.
  5. Responde las preguntas:
    • Cómo se abrirá: 1 dominio propio · 2 Cloudflare Tunnel (recomendado) · 3 solo red local.
    • El dominio (por ejemplo app.multitec.com.do) o, para red local, el nombre del servidor.
    • ¿Restaurar los datos encontrados? → s.
    • Clave del usuario postgres → la que anotaste en B3.
  6. Espera a que termine (10–20 minutos). Al final dice «Multitec quedó instalado» y la dirección para abrirlo.

¿Quieres revisar antes sin cambiar nada? En PowerShell, dentro de C:\Multitec:

powershell -ExecutionPolicy Bypass -File deploy\instalar-servidor.ps1 -SoloRevisar

DAbrir Multitec a internet

Opción recomendada: Cloudflare Tunnel

No abre puertos del router, funciona aunque el internet tenga IP compartida y Cloudflare filtra los ataques (el único caso que el servidor solo no puede frenar).

  1. Crea una cuenta gratis en cloudflare.com y agrega tu dominio (Cloudflare te dice qué servidores DNS poner donde compraste el dominio).
  2. En Cloudflare: Zero Trust → Networks → Tunnels → Create a tunnel → tipo Cloudflared → nombre multitec.
  3. Copia el comando de instalación para Windows que te muestra y ejecútalo en el servidor (PowerShell como administrador). Instala el servicio del túnel.
  4. En Public Hostname: subdominio app, tu dominio, tipo HTTP, URL 127.0.0.1:8080. Guarda.
  5. Para la página de inicio en el dominio principal, agrega otro hostname sin subdominio apuntando a la misma URL.

Más detalle en deploy\DOMINIO.md.

Opción B: dominio directo al servidor

  1. Donde compraste el dominio, crea un registro A que apunte a la IP pública del servidor.
  2. En el router, reenvía los puertos 80 y 443 a la IP del servidor.
  3. Caddy saca el certificado HTTPS solo, en un par de minutos.

ERevisar que todo esté bien

  • Abre la dirección del servidor: sale el inicio de sesión.
  • Entra con tu usuario de siempre (con los datos restaurados) o con la clave temporal que mostró el instalador (base nueva).
  • Revisa clientes, proyectos y una cotización: abre su PDF.
  • Abre /web: la página de inicio con planes y aliados.
  • Desde un celular con datos (no el wifi de la oficina), abre la dirección: debe cargar con candado (HTTPS).
  • En el panel: Plataforma → abre una empresa → «Entrar como soporte» y sal.
  • Al día siguiente: en C:\MultitecBackups debe haber una copia nueva de las 2:00 a. m.
  • En los celulares de los técnicos: abrir la dirección nueva → Compartir → «Agregar a pantalla de inicio».
La PC vieja: cuando todo funcione en el servidor, deja de usar Multitec ahí (o apágalo) para que nadie guarde datos en el lugar equivocado. Borra el ZIP de datos de la USB.

FActualizar a una versión nueva

  1. En tu PC: EMPAQUETAR.bat (solo el programa; los datos ya están en el servidor).
  2. En el servidor: extrae el ZIP nuevo encima de C:\Multitec (reemplazar archivos). No toca backend\.env, la base ni las fotos.
  3. Ejecuta INSTALAR.bat otra vez: detecta que ya está instalado, actualiza la base y reinicia los servicios.

Si algo falla

Qué pasaQué hacer
«Falta Python» o «Falta PostgreSQL»Repite B2 o B3 y vuelve a ejecutar INSTALAR.bat.
«No pude entrar a PostgreSQL con esa clave»Es la clave del usuario postgres que pusiste en B3.
«El puerto 8000 ya lo usa otro programa»Otro sistema usa ese puerto en el servidor; avísame para cambiarlo.
La página no abreMira backend\logs\backend.err.log y deploy\logs\web.err.log. En Servicios de Windows, MultitecBackend y MultitecWeb deben estar «En ejecución».
Quiero ver qué hizo el instaladorRegistro completo en deploy\logs\instalacion_….log.

Comandos útiles (PowerShell como administrador):

Restart-Service MultitecBackend, MultitecWeb      # reiniciar Multitec
Get-Service Multitec*                               # ver si están funcionando
Start-ScheduledTask -TaskName MultitecPostgresBackup  # sacar una copia ahora
